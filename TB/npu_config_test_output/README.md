# NPU Config模块测试

## 概述
本目录包含用于测试 `npu_config.v` 模块的测试平台和脚本。

## 文件说明
- **tb_npu_config_test.v**: Verilog测试平台，包含16个综合测试用例
- **run_tb_npu_config.ps1**: 编译和运行测试的PowerShell脚本
- **npu_config_test_output/**: 生成文件的目录
  - `tb_npu_config`: 编译后的仿真可执行文件
  - `test_log.txt`: 完整的测试执行日志
  - `README.md`: 测试文档（本文件）

## 测试用例

### 测试1：复位后默认值检查
验证所有寄存器在复位后具有正确的默认值：
- REG_CTRL = 0x00000000
- REG_M = 8, REG_N = 8, REG_K = 8
- REG_TILE_MASK = 0xFFFFFFFF
- REG_ITERATIONS = 1
- 输出端口与默认值一致

### 测试2：基本寄存器读写回环测试
测试M、N、K维度寄存器的基本读写操作：
- 写入 M=16, N=32, K=64
- 读取并验证写入值
- 验证输出端口更新

### 测试3：模式寄存器写入
验证模式寄存器配置：
- 设置模式为 MERGE (01) + 静态权重(bit2=1) + 独立模式(bit3=1)
- 写入值：0x0000000C
- 验证 cfg_mode 输出正确提取低2位

### 测试4：Tile掩码和迭代次数寄存器
测试Tile掩码和迭代计数寄存器的操作：
- 写入 TILE_MASK = 0x0000FFFF
- 写入 ITERATIONS = 8
- 验证读取值和输出端口

### 测试5：启动脉冲生成
验证向REG_CTRL写入bit0时产生单周期启动脉冲：
- 第一个周期：cfg_start = 1
- 第二个周期：cfg_start = 0

### 测试6：状态清除脉冲生成
验证向REG_CTRL写入bit1时产生单周期清除脉冲：
- 第一个周期：cfg_status_clr = 1
- 第二个周期：cfg_status_clr = 0

### 测试7：中断使能寄存器
测试完成和错误中断的中断使能寄存器：
- 写入 IRQ_EN = 0x00000003（同时使能done和error）
- 验证 irq_en_done 和 irq_en_error 输出

### 测试8：状态寄存器读取
验证在不同完成/错误标志组合下读取状态寄存器：
- done=1, error=0 → 读取 0x00000001
- done=0, error=1 → 读取 0x00000002
- done=1, error=1 → 读取 0x00000003

### 测试9：计算锁定机制
关键测试，验证计算期间的寄存器保护：
- **被锁定的寄存器**（computing=1时不可写）：
  - REG_M、REG_N、REG_K
  - REG_MODE
- **不被锁定的寄存器**（computing=1时仍可写）：
  - REG_TILE_MASK
  - REG_ITERATIONS
  - REG_IRQ_EN
  - REG_CTRL（启动脉冲可在计算期间生成）
- 清除computing标志后，所有寄存器恢复可写状态

### 测试10：多次连续写入
测试对多个寄存器的快速连续写入以确保正常运行：
- 连续写入 M=24, N=48, K=96, TILE_MASK=0xF0F0F0F0, ITERATIONS=16
- 等待2个周期后依次读取验证

### 测试11：模式寄存器枚举测试
验证三种工作模式的正确配置：
- **INDEP模式**：mode[1:0] = 2'b00 → cfg_mode = 00
- **MERGE模式**：mode[1:0] = 2'b01 → cfg_mode = 01
- **SPLIT模式**：mode[1:0] = 2'b10 → cfg_mode = 10

### 测试12：M/N/K边界值测试
测试维度寄存器的边界值和溢出行为：
- **最小值测试**：M=N=K=0，验证正常读写
- **最大值测试**：M=N=K=63（6位最大值），验证寄存器存储完整32位值，输出端口正确截断为6位
- **溢出测试**：K=64，验证：
  - 寄存器存储完整值64
  - cfg_k输出截断为0（6位溢出）

### 测试13：计算锁定期间的启动脉冲
验证REG_CTRL在计算锁定期间仍可生成启动脉冲：
- 设置 computing=1
- 写入 REG_CTRL=0x01
- 验证 cfg_start 仍能产生脉冲（REG_CTRL不被锁定）
- 验证脉冲在第二周期返回0

### 测试14：计算期间非锁定寄存器测试
验证特定寄存器在计算期间仍可写入：
- **REG_ITERATIONS**：写入15，验证可写
- **REG_IRQ_EN**：写入0x01，验证可写
- 确认这些寄存器不受computing标志影响

### 测试15：REG_CTRL同时启动+清除
验证REG_CTRL同时设置bit0和bit1时的行为：
- 写入 REG_CTRL=0x03（bit0=1, bit1=1）
- 验证 cfg_start 和 cfg_status_clr 同时拉高
- 验证两个脉冲都在第二周期返回0

### 测试16：异步复位恢复测试
验证异步复位的正确行为：
- 设置非默认值（M=32, N=48, K=16等）
- 拉低 rst_n（不等待时钟边沿）
- **立即检查**：输出端口应恢复默认值（M=N=K=8）
- 释放复位后验证所有寄存器恢复默认值：
  - REG_M=8, REG_MODE=0
  - REG_TILE_MASK=0xFFFFFFFF
  - REG_ITERATIONS=1

### 测试17：非法地址解码测试
验证对非法地址的访问行为：
- **写非法地址**（0x03、0xFF、0x05）：
  - 验证合法寄存器值不受影响
  - 确认无副作用或错误状态
- **读非法地址**：
  - 验证返回值为0
  - 确保不会读取到随机值或X态
- **关键发现**：非法地址访问被安全忽略，系统保持稳定

### 测试18：多周期wr_en毛刺容忍测试
验证总线毛刺对寄存器稳定性的影响：
- 施加持续多个周期的 wr_en 信号（模拟总线毛刺）
- 验证寄存器值保持稳定，不受额外周期影响
- 确认只有第一个有效周期的写入被接受
- **关键发现**：寄存器对总线毛刺具有鲁棒性

### 测试19：背靠背start脉冲测试
验证连续启动脉冲的正确生成：
- 第一次写入 REG_CTRL=0x01，生成start脉冲
- 立即第二次写入 REG_CTRL=0x01，再次生成start脉冲
- 验证两次脉冲都正确产生且互不干扰
- 验证每次脉冲都是单周期宽度
- **关键发现**：支持高频连续启动操作

### 测试20：写只读STATUS寄存器测试
验证对只读寄存器的写保护：
- 尝试向 REG_STATUS 写入任意值
- 验证写操作被完全忽略
- 确认 STATUS 仍然反映实际的 status_done 和 status_error 输入
- 验证无法通过写操作篡改状态标志
- **关键发现**：只读寄存器写保护机制有效

## 如何运行

### 前置条件
- 已安装Icarus Verilog并添加到PATH
- 可用的PowerShell环境

### 执行命令
``powershell
cd TB
.\run_tb_npu_config.ps1
```

脚本将执行以下操作：
1. 使用 `iverilog` 编译测试平台
2. 使用 `vvp` 运行仿真
3. 将所有输出保存到 `npu_config_test_output/test_log.txt`
4. 在终端中显示结果，带有颜色编码的通过/失败指示

## 被测模块
`npu_config` 模块提供：
- 通过AXI-Lite接口的配置寄存器存储
- 启动和状态清除信号的脉冲生成
- 计算锁定机制，防止操作期间关键参数更改
- 反映NPU操作状态的状态寄存器
- 中断使能控制
- 异步复位支持

## 注意事项
- 测试平台使用辅助任务（`write_reg`、`read_reg`、`wait_cycles`）实现清晰的测试代码
- 所有寄存器地址在 `npu_defs.vh` 中定义
- 测试使用 `$monitor` 监控信号转换以便调试
- 仿真在约1.5微秒内完成
- 新增测试覆盖了边界值、模式枚举、异步复位等关键场景

## 常见问题

### Q1: 编译失败
**原因**: Icarus Verilog未安装或不在PATH中  
**解决**: 安装Icarus Verilog并确保`iverilog`和`vvp`命令可用

### Q2: 测试失败
**原因**: 模块逻辑错误或测试用例问题  
**解决**: 检查日志文件中的详细失败信息，定位具体失败的测试用例

### Q3: 日志文件格式混乱
**原因**: PowerShell输出处理不当  
**解决**: 当前版本已修复，使用临时文件捕获输出以保留换行符

### Q4: 某些边界测试失败
**可能原因**: 
- 位宽截断逻辑错误
- 异步复位时序问题
- 锁定机制实现不完整

**解决**: 查看对应测试的详细输出，对比期望值和实际值
